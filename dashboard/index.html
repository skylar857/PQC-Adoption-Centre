Method and limitations

  • Each host gets one TLS 1.3 handshake with OpenSSL 3.5, offering X25519MLKEM768 first and X25519 as fallback. The group the server picks is recorded. If the hybrid offer fails, a classical-only control handshake is tried.
  • Percentages use reachable hosts as the denominator. Unreachable and timed-out hosts are reported separately.
  • Sample sizes for the Indian categories are small, so the confidence intervals are wide. Most differences between categories are not statistically significant.
  • This measures server-side support at one point in time from one vantage point (Chennai, India). It does not measure browser adoption.
  • Many sites get hybrid support from a CDN in front of them, so a hybrid result does not always mean the site operator enabled it.
  • Only the key exchange is hybrid. Certificates and signatures are still classical.
  • The Tranco top list includes some infrastructure domains that are not websites.
  • Handshake cost rows are estimates built from openssl speed results, run in Docker on WSL2.
